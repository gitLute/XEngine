# Бриф ревизии XEngine.Mathematics: закрытие дефектов уровня P2

Бриф написан один раз и далее только дополняется. Задача сессии: **исправить
открытые дефекты уровня P2**, перечисленные в `revision/REGISTRY.md`.

---

## 1. Предмет ревизии, границы, что нельзя трогать

**Предмет.** Библиотека `src/XEngine.Mathematics` (31 файл `.cs`, 11 365 строк).
Основание для работы — `Problems.md`, раздел 1.2 и подраздел «Два дефекта,
найденные шестой ревизией». Анализ уже выполнен предыдущими ревизиями и
записан в документе; **эта сессия — волна починки**. Первым шагом каждого
исправителя является проверка, что дефект воспроизводится на текущем коде:
цифра, попавшая в документ, переписывается только новым измерением.

**Владение файлами.** У каждого исправителя своя подсистема и **ровно один
новый тестовый файл**. Соседние подсистемы и чужие тестовые файлы не

**Читать можно всё.** Граница запрещена на **правку**, а не на чтение:

применено, а здесь нет».

**Общие файлы — только владелец ревизии.** Запрещено править: `README.md`,
`ARCHITECTURE.md`, `Problems.md`, `Directory.Build.props`, `.editorconfig`,
`.gitignore`, любой `.csproj`, `XEngine.sln`, любой файл в
`tests/XEngine.Architecture.Tests/`, любой **чужой** тестовый файл в
`tests/XEngine.Mathematics.Tests/`.

**Исключение, требующее моего решения.** Два существующих теста красные до
начала работы (см. §2). Если выясняется, что неправда в доктрине теста, а не в
коде, исправитель **не переписывает тест**, а приносит вердикт с измерением в
раздел «Требует вмешательства владельца». Переписывание доктрины существующего
теста — решение владельца кода.

## 2. Профиль проекта

Проверен измерением на этой сессии, не перенесён из документа.

| что | значение |
|---|---|
| система сборки | MSBuild, .NET SDK **10.0.112** (`dotnet --version`) |
| рантайм | `net10.0`, `LangVersion=latest`, `Nullable=enable` |
| тест-раннер | xunit **2.9.2**, `Microsoft.NET.Test.Sdk` 17.11.1, `xunit.runner.visualstudio` 2.8.2 |
| библиотека | `src/XEngine.Mathematics/XEngine.Mathematics.csproj`, без внешних пакетов |
| тесты математики | `tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj` |
| правила целостности | `tests/XEngine.Architecture.Tests` — сканирует **только `src/`**, пропускает `bin`/`obj` |

### Две конфигурации сборки — обе обязательны

Проект имеет два математических backend, переключаемых свойством `MathBackend`
(`Fast` по умолчанию, `Deterministic` — многочлены вместо `MathF`). Обе
сборки проходят один и тот же набор тестов, и **правка, верная в одной,
ломает другую — проявится именно там**.

- **Быстрая:** конфигурация `Release`, `MathBackend=Fast` (значение по умолчанию).
- **Детерминированная:** конфигурация `Deterministic` (свойство само ставит
  `MathBackend=Deterministic`) либо `-p:MathBackend=Deterministic` при `Release`.

### Команды — дословно, рабочие

```bash
# сборка библиотеки и тестов (обязательна с -warnaserror)
dotnet build tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj -c Release -warnaserror

# тесты, быстрый backend
dotnet test tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj -c Release

# тесты, детерминированный backend
dotnet test tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj -c Deterministic

# правила целостности (запреты по src/)
dotnet test tests/XEngine.Architecture.Tests/XEngine.Architecture.Tests.csproj -c Release
```

### Изоляция артефактов сборки — проверена пробным параллельным прогоном

Три параллельные сборки с раздельными каталогами артефактов дали **ноль
ошибок сборки** и одинаковый результат тестов.

```bash
# каталог артефактов агента — только свой, общий запрещён
dotnet build  tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj -c Release -warnaserror \
             --artifacts-path revision/tmp/w2/<агент>/art
dotnet test   tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj -c Release --no-build \
             --artifacts-path revision/tmp/w2/<агент>/art
dotnet test   tests/XEngine.Mathematics.Tests/XEngine.Mathematics.Tests.csproj -c Deterministic \
             --artifacts-path revision/tmp/w2/<агент>/art
```

**Чего делать нельзя:** `-p:BaseOutputPath` / `-p:BaseIntermediateOutputPath`
ломают исключения SDK — старая папка `obj/` попадает в компиляцию и сборка
падает с `CS0579: Duplicate ... AssemblyInfo`. Проверено, использовать только
`--artifacts-path`.

### Замеры скорости

Отдельного проекта-бенчмарка в репозитории **нет**, все числа в `Problems.md`
получены временными зондами. Свой зонд исправитель собирает сам: отдельный
консольный проект в своём каталоге `revision/tmp/w2/<агент>/bench/` со
`ProjectReference` на `src/XEngine.Mathematics`. Каталог `src/` для зондов
запрещён — его сканирует `XEngine.Architecture.Tests`.

Требования к замеру: несколько раундов, брать лучший; аргументы не должны
выноситься оптимизатором из цикла (иначе мера меряет не то и обе версии дают
правдоподобные бессмысленные числа); методика проверяется на дефектном коде.

## 3. Требования к коду

### Корректность

- **Независимый эталон, написанный ревизией.** Другая точность типа или другая
  реализация того же расчёта. Наивный эталон соврёт вместе с кодом, потому что
  повторит ту же ошибку. Для `float`-математики эталон считается в `double`,
  для граничных сравнений — через приведение, для длин — через `hypot`-подобную
  норму, не через `sqrt(x²+y²)`.
- **Дискриминирующий контрпример.** Проверка обязана давать **разный** ответ на
  исправленном и на исходном коде. Проверка, которая на всех входах отвечает
  одинаково, ничего не проверяет.
- **Подсказка из задачи, а не константа.** Контрольный пример должен быть
  таким, чтобы отмена правки была видна. Константа, подогнанная под ожидаемый
  ответ, не доказывает ничего.
- **Вырожденные входы обязательны:** пустой контейнер, нулевой вектор, совпадающие
  границы, `min > max`, `NaN`, `±Infinity`, нулевой знаменатель, переполнение,
  значения у границ диапазона `float` и `int`.

### Оптимизация

- Замер **до и после**, в обеих конфигурациях, несколько раундов, брать лучший.
- Цена правильности **непредсказуема и должна быть измерена заранее**: та же
  правка в одном классе стоила `+22 %`, в другом с тем же приёмом `+1.6 %`.
- Оптимизация без замера не объявляется. Если правка не меняет результат
  принципиально, её полезность измеряется замером, а не тестом, и это пишется
  в доктрину явно.

### Тесты

- На каждое исправление — **новый** тест в своём файле. Тест обязан падать на
  прежнем коде.
- Внутри цикла — **только счётчик**, одна проверка после. Проверка на каждой
  итерации копит записи и выглядит как зависание без вывода.
- Полный набор прогоняется **в конце, в обеих конфигурациях**, плюс
  `XEngine.Architecture.Tests`.

### Внешние источники

Обязательны, когда дефект касается поведения внешней спецификации, формата,
протокола или алгоритма (`System.Text.Json`, поведение `MathF`, слияние FMA
компилятором, правила `NumberStyles`). Источник указывается явно: что именно оттуда
взято и в каком виде. Неприменимый инструмент **называется прямо**, а не
подменяется ссылкой на память.

## 4. Инфраструктура: замеры, обратный ход, обе конфигурации

1. **Воспроизведение до правки.** Первое действие исправителя: убедиться, что
   дефект **воспроизводится на текущем коде**, и записать числа. Дефект, который
   не воспроизвёлся, не чинится — он идёт в отчёт как опровергнутая гипотеза
   с измерением. Это не провал работы, это результат.
2. **Эталон и дискриминирующий тест.** Пишутся **до** правки.
3. **Правка.** Минимальная, по причине, а не по симптому. Если семь мест лечатся
   одной причиной — правится одна причина, и отмечается, где та же болезнь ещё
   не проявилась.
4. **Обратный ход.** Правка откатывается **в scratch-копии**, проверка обязана
   упасть, число упавших проверок записывается. Откат делается **только в
   scratch**, никогда перезаписью файлов на месте: пока идёт откат, соседний
   агент собирает библиотеку с откатанным кодом, а снимок, наложенный поверх
   новых правок, уничтожает их молча.
   Ноль упавших проверок означает, что правка не наблюдаема, и это фиксируется
   явно, а не прячется.
5. **Замеры до и после** по каждой правке, меняющей время выполнения.
6. **Обе конфигурации** плюс `XEngine.Architecture.Tests`.
7. **Границы проверяются на приёмке**, а не предполагаются: по диффу видно,
   какие файлы изменены.

**Измеренные цены правок, известные заранее** (брать как ориентир, а не как
ожидаемое число):

| правка | цена |
|---|---|
| замена абсолютного порога `Epsilon²` на точный ноль в `Capsule2` | `Collision.Intersects(Capsule2)` `18.1 → 22.0 нс`, **+21 %**. Документ прямо предупреждает: **если тот же приём применять к `Capsule3`, цена сложится там же — проверка обязательна** |
| оговорка вместо порога в `MoveTowards` | 249 790 нарушений `maxStep` из 500 000 → 0, и правка **на 11 % быстрее** |
| ограничение сдвига в `SurfaceRadius` | на 2 000 000 конфигураций меняет 34 338 точек, и **на всех** из них текущий код уже был неправилен — мест, где он верен, ноль |

## 5. Запреты

Сбой, уже случившийся в исходной сессии. Повторение любого стоит дороже всего
остального вместе взятого.

| сбой | последствие | правило |
|---|---|---|
| массовое убийство процессов по шаблону имени | погасил пять сессий агентов вместе с собой | **никаких `pkill`, `killall`, `kill`**. Свои прогоны ограничивать `timeout`; имя зависшего теста узнавать через режим виновника раннера (`--blame-hang --blame-hang-timeout`), если он есть |
| цикл до максимума целочисленного типа | переполнение даёт бесконечный цикл, прогон висел на полной загрузке 15 минут | границы циклов у предела типа проверять глазами **до** запуска |
| проверка внутри цикла на сотнях тысяч итераций | раннер копит записи — выглядит как зависание | внутри цикла только счётчик, одна проверка после |
| пробник с выводом на каждой итерации | 19 700 строк вытеснили начало задания, агент умер до первой правки | вывод в файл, в консоль не печатать; на миллионных циклах — агрегаты. Перед чтением файла измерений — `wc -l`, дальше `head`, `tail`, `grep` |
| агент читал файл измерений целиком | объёмный файл съедает контекст | проверять объём до чтения |
| исчерпание лимита запросов | часть сессий упала | возобновлять ту же сессию по её `sessionID`, задачу **не сокращать** |
| откат правки перезаписью файлов на месте | стёр собственные правки молча, пока соседи собирали библиотеку с откатанным кодом | обратный ход **только в scratch** |
| фильтрация истории (`git filter-branch` и подобное) | уничтожила GPG-подписи 12 подписанных коммитов | историю не фильтровать; переподпись — дело владельца в видимом окне |
| общий каталог артефактов у нескольких агентов | сборки дрались за промежуточный каталог | у каждого агента свой `--artifacts-path` |
| ошибка в брифе владельца | агент сравнивал хэш базового коммита с хэшем вершины — сравнение бессмысленно | **агенту велено не подгонять результат, а разобраться и починить меру** |
| правка объёма задания на ходу | ревизия расползлась, волна закрылась ни с чем | **новый дефект — в отчёт, не в правку** |

Дополнительно для этого проекта:

- **Никаких правок вне своей подсистемы.** Понадобилась правка в чужом файле —
  это не повод её сделать, а повод написать точный предложение в отчёт.
- **Никаких `Console` и `Debug` в `src/`** и никакой рефлексии в `src/`:
  это проверяется автоматически и роняет `XEngine.Architecture.Tests`.
- **Сборка обязана проходить с `-warnaserror`**: включены анализаторы
  (`CA1062`, `CA1819`, `CA2227`, `CA1848`, `CA2007`, `CA1031`, правила стиля и
  именования) и `TreatWarningsAsErrors`.
- **Коммитом не занимается никто, кроме владельца ревизии.** Агенты делят
  рабочее дерево, и коммит одного захватил бы незакоммиченные правки соседа
  целиком. Коммит делает владелец после приёмки волны, явным списком файлов
  агента. Это отступление от шаблона метода, внесённое сознательно.

**Поощряемое поведение.** Агент, чья проверка не прошла и который разобрался,
где ошибка в мере, и починил меру, сделал работу лучше агента с подогнанным
числом. Такое поведение **не блокируется и не запрещается**. «Расхождение 68 %»,
исчезнувшее после починки эталона, — не провал, а находка.

## 6. Требования к отчёту

Файл отчёта — **источник истины**, а не ответ в чате. Отдельный файл на
агента. Объём не ограничен, но вывод пробников в отчёт **не переносится**:
измерения живут в `revision/tmp/w2/<агент>/`, в отчёт идут числа и выводы.

```markdown
# <Подсистема> — волна 2

## Итог
Что сделано, что не сделано, сколько дефектов закрыто. 5–10 строк.
Список измеренных цен правок до и после.

## Дефекты
### <ID>. <Краткое имя>
- **Где**: <файл:строка>
- **Воспроизведение на исходном коде**: <числа ДО правки>
- **Причина**: <одна-две фразы>
- **Правка**: <что сделано>
- **Дискриминирующий контрпример**: <чем отличается исходный и исправленный код>
- **Обратный ход**: <сколько проверок упало после отката правки в scratch>
- **Замер до и после**: <числа, если правка меняет время выполнения>
- **Обе конфигурации**: <результат>

## Гипотезы, которые не подтвердились
Раздел обязателен. Что проверялось и оказалось в порядке.

## Что не удалось
Раздел обязателен и честен. Что не проверено, что помешало, какие инструменты
были недоступны.

## Требует вмешательства владельца
Раздел обязателен, даже если пуст — тогда в нём пишется «не требуется».
Вопросы контракта: сигнатуры, доктрины, новый публичный API. Формулировки
дословные, готовые к решению.
```

В отчёте обязательно указать: какие файлы изменены (список), и подтвердить, что
ничего за пределами своей подсистемы не тронуто.

## 7. Что делать, если задание требует невозможного

**Агент не имеет права решать вопросы контракта.** Новый публичный API,
изменение сигнатуры, переименование, изменение поведения, на которое
рассчитывает существующий код, изменение доктрины существующего теста, новое
исключение там, где контракт обещал другого вида, — всё это **решение владельца
кода**, а не исправителя.

Обязанность агента в такой ситуации:

1. **Остановиться на этом пункте**, не подгоняя решение.
2. **Донести вопрос в форме, готовой к решению**: точное место (файл и строка),
   что именно требуется, почему задание без этого невыполнимо, какие
   последствия для вызывающего кода, какие варианты возможны и чем они
   платят.
3. **Не мешать работу дальше**: остальные дефекты своей подсистемы закрыть.
4. Записать это в раздел «Требует вмешательства владельца» отчёта дословно.

Отдельно про измерения: если чек-лист требует числа, а честное измерение его
не даёт, агент **пишет, что числа нет и почему**. Выдуманное число хуже
отсутствующего.

## 9. Сверка списка: почему перед починкой идёт волна 1.5

На приёмке обнаружено, что `Problems.md` **отстал от кода**: два дефекта из
первой же проверенной пары уже исправлены, а документ держит их открытыми.

| дефект | что в коде на `HEAD = 3057642` |
|---|---|
| P2-53 | `Random/RandomExtensions.cs:78` — зажим `value < max ? value : MathF.BitDecrement(max)`, с измеренной ценой в доктрине: `2.861 → 3.344 нс`, **+17 %** на 2 000 000 вызовов |
| P2-50 | `Graphics/Rgba32.cs:96-121` — ручной разбор таблицей `HexDigits`, а не `NumberStyles.HexNumber`; пробел даёт `InvalidHexByte` и `FormatException` |

Оба прочитаны мной, а не измерены, поэтому это **подсказка, а не вердикт**.

Из этого следует порядок работ: **ни один исправитель не запускается, пока его
пункты списка не подтверждены измерением на текущем коде.** Поэтому между
анализом предыдущих ревизий и починкой вставлена волна 1.5 — сверка списка.
Аналитик этой волны **не ищет новых дефектов**: новый дефект — это запись в
отчёт владельцу, а не предмет правки и не предмет этой волны.

Иначе получается ровно то, что метод называет полем чужих правок: агент
«чинит» код, который уже исправлен, и либо вносит ненужную правку, либо
тратит бюджет на доказательство того, что доказывать нечего.
