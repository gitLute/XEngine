# AtlasBuilder

Инструмент сборки текстурных атласов. Лежит вне слоёв решения и не является
частью движка: он не ссылается ни на один проект из `src/` и не попадает в
выдачу игры (5.2, 5.5).

## Зачем

Атлас объединяет несколько текстур в одну, чтобы сократить число переключений
текстур и использовать единый набор материалов (10.6). Проверки UV-подстановки,
`fract` при тайлинге и отсечения региона на этапе 9 требуют настоящего атласа с
регионами невыровненных границ, а написанные руками координаты в JSON таким
атласом не являются. Поэтому сборка атласа автоматизирована и лежит в
репозитории (21.4a).

## Запуск

```bash
dotnet run --project tools/AtlasBuilder -- \
  --source assets/textures/source \
  --output assets/textures
```

| Аргумент | Значение |
|---|---|
| `--source` | каталог с описанием регионов; по умолчанию читается `<каталог>/world.json` |
| `--output` | каталог для `atlas.png` и `atlas.json`; создаётся при необходимости |
| `--atlas` | имя описания без расширения, по умолчанию `world` |
| `--help` | справка |

Коды возврата: `0` — атлас собран, `1` — описание или исходники противоречат друг
другу, `2` — неверные аргументы.

## Вход

`assets/textures/source/world.json`:

```json
{
  "name": "world",
  "width": 64,
  "height": 32,
  "bleedingPixels": 2,
  "regions": [
    {
      "name": "stone",
      "source": "stone.png",
      "rect": { "x": 0, "y": 0, "width": 32, "height": 32 },
      "sizeTexels": { "x": 32, "y": 32 },
      "texelsPerMeter": 16
    }
  ]
}
```

Границы прямоугольников включительные: `0,0,32,32` — это 32 пикселя по каждой
оси. Так же они считаются в движке у `AtlasRegion.PixelRect`, и расхождение на
один пиксель здесь проявилось бы только в кадре.

## Выход

`atlas.png` и `atlas.json` в формате 14.2. Описание содержит те же
прямоугольники в пикселях готового атласа, размеры в текселях и рекомендуемую
плотность. `AtlasBleedingPixels` в конфигурации движка задаётся сборщиком
(14.1), поэтому полоса между соседними регионами здесь параметр описания, а не
константа в коде.

## Что проверяется

- регион целиком внутри атласа;
- регионы не накладываются и между соседями остаётся полоса `bleedingPixels`;
  без неё билинейная фильтрация подмешивает соседний регион;
- имя региона не повторяется и не пустое;
- размер региона совпадает с размером в описании и с размером файла исходника;
- рекомендуемая плотность положительна.

## Чего инструмент пока не делает

Пиксели регионов не копируются: на этапе 1 проверяется геометрия, а собранный
атлас пустой. Растеризация вынесена в `IAtlasRasterizer`, а пустая реализация
названа `BlankRasterizer`, чтобы подмена не прошла молча. Копирование пикселей
появляется на этапе 9 вместе с тестами UV-подстановки.

## Зависимости

Внешних пакетов нет. PNG читается по заголовку (сигнатура и блок IHDR) и
пишется вручную: `System.IO.Compression.ZLibStream` даёт поток zlib, которого
требует формат PNG, а CRC считается таблицей в `PngWriter`. Сериализация JSON
идёт через контекст исходного кода, а не через рефлексию: правило
отсутствия рефлексии (инвариант 2) действует и для инструмента.

## Проверка

```bash
dotnet test tests/AtlasBuilder.Tests
```

Тесты строят атлас из двух текстур во временном каталоге, проверяют все отказы
и разбирают собранный PNG обратно. Отдельный тест идёт по исходникам из
`assets/textures/source`, поэтому пример в репозитории и код проверяются одним
и тем же путём.
